# 买入判定模块设计

## 背景

用户需要一个新的“决策判定”一级功能模块，与“持仓管理”同级。第一期只提供一个页面：“买入判定”。页面内容与判断逻辑参照既有原型 `C:\Users\wujian\Documents\Codex\2026-08-27\wo-x\outputs\index.html`。

本次采用纯前端实现，不新增后端 API、数据库表或决策记录持久化。

## 产品行为

页面标题为“买入判定”，副标题说明是本地规则判断，不联网、不查行情。

用户依次选择：

1. 买入原因：蓝筹长期持有、追热点/跟风、回调抄底、潜伏中期、大V推荐、小V推荐、就是想买点试试、暴跌抄底。
2. 股票种类：蓝筹、成长、概念、龙头、二线杂毛；选项按买入原因过滤。“蓝筹长期持有”不显示种类选择。
3. 股价位置：高位、中位、低位。“暴跌抄底”把这一步改为“时机”：当日、次日及以后。

三类选择完成后展示判定结果：

- 判定档位：别买、观察、轻仓、正常、重仓、超重仓。
- 建议投入：0、1、2、4、6、8 万元，与档位一一对应。
- 结果色：别买为红色，观察/轻仓为警告色，正常为品牌色，重仓/超重仓为绿色。
- 进度条按建议投入除以 8 显示比例。
- 说明文案按选中项生成，特殊规则优先使用固定解释。

用户可以点击“重新选择”清空第 2、3 步和结果，并保留第 1 步当前选项便于快速重算。

## 判定规则

常规买入原因使用分数：原因基础分 + 股价位置分 + 股票种类分。

| 买入原因       | 基础分 | 允许种类         | 特殊约束     |
| -------------- | -----: | ---------------- | ------------ |
| 蓝筹长期持有   |      2 | 不选择种类       | 0            |
| 追热点/跟风    |      0 | 龙头、二线杂毛   | 高位禁买     |
| 回调抄底       |      2 | 蓝筹、成长、概念 | 高位禁买     |
| 潜伏中期       |      0 | 蓝筹、成长、概念 | 使用专门表   |
| 大V推荐        |      4 | 蓝筹、成长、概念 | 0            |
| 小V推荐        |      2 | 蓝筹、成长、概念 | 0            |
| 就是想买点试试 |     -2 | 蓝筹、成长、概念 | 使用专门表   |
| 暴跌抄底       |      0 | 蓝筹、成长、概念 | 使用时机规则 |

位置分：高位 -2，中位 0，低位 2。种类分：蓝筹 2，龙头 2，成长 0，概念 -2，二线杂毛 -3。分数映射：0 及以下为别买，1 为观察，2 为轻仓，3-4 为正常，5-6 为重仓，7 及以上为超重仓。

专门规则优先于分数计算：

- 暴跌抄底：当日为别买；次日及以后，蓝筹为正常，成长/概念为别买。
- 就是想买点试试：高位别买，中位观察，低位轻仓。
- 潜伏中期：高位别买；低位蓝筹为正常，低位成长/概念为轻仓；中位蓝筹为轻仓，中位成长/概念为观察。
- 回调抄底高位、追热点高位：直接别买。

## 前端结构

新增路由：

- `/decision`：一级模块“决策判定”，图标选择一个现有 Element Plus 图标，默认重定向到 `/decision/buy-check`。
- `/decision/buy-check`：页面“买入判定”。

新增文件：

- `src/views/decision/BuyDecision.vue`：页面交互和展示。
- `src/views/decision/buyDecisionRules.js`：规则常量、选项过滤、分数映射、判定计算。
- `src/views/decision/buyDecisionRules.test.js`：规则单元测试。

修改文件：

- `src/router/routes.js`：新增决策判定模块。

`BuyDecision.vue` 使用 Element Plus 组件和现有页面风格实现卡片、步骤、选项按钮、结果区、进度条和说明。规则模块保持无 Vue 依赖，便于 Vitest 覆盖常规打分、专门规则、高位禁买和档位映射。

## 错误与边界

- 用户选择原因后重置后续选择，避免上一原因的无效种类或位置残留。
- 所有选项来自规则模块，页面不允许定义第二套硬编码规则。
- 未完成三类选择时不展示结果。
- 判定结果为“别买”时建议投入仍显示 0 万元。

## 验收

- 侧边栏出现“决策判定”，展开后只有“买入判定”。
- 页面可按参照原型完成三步选择并输出档位、建议投入、进度条和说明。
- “重新选择”保留买入原因并清空后续选择和结果。
- 常规打分、四类专门规则、档位映射均有单元测试覆盖。
- `npm run check` 通过。
